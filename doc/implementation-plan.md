## Этап 1. Закрыть блокеры фронтенда

### 1. Профиль текущего пользователя

- [ ] Реализовать `GET /api/v1/profile`.
- [ ] Возвращать ID, ФИО, дату рождения, email, Telegram username, активную роль и список назначенных ролей.
- [ ] Возвращать permissions, необходимые для построения меню.
- [ ] Добавить изменение допустимых полей профиля.

Критерий готовности: после перезагрузки страницы фронт может восстановить состояние пользователя без декодирования JWT как единственного источника данных.

### 2. Получение ролей для самостоятельного выбора

- [x] Добавить `GET /api/v1/roles/self-assignable` для авторизованного пользователя.
- [x] Возвращать только роли с `self_assignable = true`.
- [x] Не возвращать системные и административные роли.
- [x] Добавить тест запрета самостоятельного выбора системной роли.

Критерий готовности: экран выбора роли не содержит захардкоженных ID.

### 3. Документы регистрации

- [x] Выбрано локальное приватное хранилище для MVP.
- [x] Документы принимаются внутри `POST /api/v1/auth/register`, отдельного публичного upload endpoint нет.
- [x] Разрешены PDF/JPEG/PNG/XML/DOCX; проверяется фактическое содержимое и размер.
- [x] File ID не принимаются от клиента и используются только внутри backend.
- [x] Привязка файлов к согласиям выполняется в транзакции с блокировкой `FOR UPDATE`.
- [x] Доступ к скачиванию ограничен владельцем либо permission `files.read`.
- [x] Добавить периодический запуск очистки записей `uploaded`/`delete_pending`, оставшихся после аварийного завершения процесса.
- [x] Настроить постоянный Docker volume и путь хранилища через environment.

Критерий MVP выполнен: взрослый и несовершеннолетний пользователь могут пройти регистрацию одним запросом, а обязательность родительского файла определяется backend по возрасту.

### 4. CORS и frontend-конфигурация

- [x] Добавить список разрешённых origins через environment.
- [x] Разрешить необходимые методы и заголовок `Authorization`.
- [x] Корректно обрабатывать preflight `OPTIONS`.
- [x] Добавить `API_BASE_URL` в frontend environment.

Критерий готовности: frontend и backend работают на разных origins без отключения browser security.
