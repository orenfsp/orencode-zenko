# API судейской коллегии соревнования

API использует существующую таблицу `competition_judge`. Назначение связывает соревнование, пользователя с ролью `judge` и запись справочника `judge_position`. Пользователь и его роли при снятии назначения не удаляются.

## Получение судейской коллегии

```http
GET /api/v1/competitions/{id}/judges
```

Авторизация не требуется. Endpoint доступен только для публичных статусов соревнования: `published`, `registration_open`, `registration_closed`, `ongoing`, `results_pending`, `completed`. Для отсутствующего или непубличного соревнования возвращается `404`.

```json
{
  "data": [
    {
      "id": 15,
      "competition_id": 7,
      "judge": {
        "id": 42,
        "first_name": "Иван",
        "last_name": "Иванов",
        "middle_name": "Иванович"
      },
      "position": {
        "id": 1,
        "name": "Главный судья"
      },
      "appointed_at": "2026-10-27T10:00:00Z"
    }
  ]
}
```

Если назначений нет, возвращается `{"data":[]}`.

## Назначение судьи

```http
POST /api/v1/competitions/{id}/judges
Authorization: Bearer <access_token>
Content-Type: application/json
```

Требуется permission `competition_judges.manage`.

```json
{
  "judge_user_id": 42,
  "position_id": 1
}
```

Пользователь должен существовать и иметь назначенную через `role_user` роль с кодом `judge`. Судейская должность должна существовать в `judge_position`. Для MVP назначение разрешено только соревнованиям со статусом `draft`.

Успех: `201 Created`.

```json
{
  "data": {
    "id": 15,
    "competition_id": 7,
    "judge_user_id": 42,
    "position_id": 1,
    "appointed_at": "2026-10-27T10:00:00Z"
  }
}
```

Повторное назначение того же пользователя на ту же должность в том же соревновании возвращает `409 Conflict`.

## Снятие назначения

```http
DELETE /api/v1/competitions/{id}/judges/{assignmentId}
Authorization: Bearer <access_token>
```

Требуется permission `competition_judges.manage`. Удаляется только строка `competition_judge`, причём только если она принадлежит соревнованию из URL. Для MVP операция разрешена только у `draft`.

Успех: `204 No Content` без тела. Отсутствующее или принадлежащее другому соревнованию назначение возвращает `404`.

## Основные коды ответов

| Код | Значение |
|---:|---|
| `200` | список получен |
| `201` | судья назначен |
| `204` | назначение удалено |
| `400` | неверный JSON/ID или пользователь не имеет роли `judge` |
| `401` | отсутствует или недействителен access-токен для изменения |
| `403` | нет `competition_judges.manage` |
| `404` | соревнование, пользователь, должность или назначение не найдены |
| `409` | повторное назначение либо изменение не-черновика |
| `500` | внутренняя ошибка без раскрытия деталей PostgreSQL |

## Ограничение конкурентных назначений

Статус `draft` проверяется не только в Service, но и внутри SQL `INSERT/DELETE`; строка соревнования блокируется `FOR UPDATE`, поэтому операция согласована с конкурентной сменой статуса. Дубликат проверяется и до вставки, и внутри `INSERT`, но в актуальной схеме нет уникального ограничения на `(competition_id, judge_user_id, position_id)`. Поэтому два строго одновременных одинаковых назначения теоретически всё ещё могут создать дубликат. Абсолютная гарантия потребует отдельной согласованной миграции с уникальным индексом; эта задача схему БД не изменяет.
## Справочник судейских должностей

```http
GET /api/v1/judge-positions
```

Ручка публичная и возвращает список доступных должностей для формы назначения судьи:

```json
{
  "data": [
    { "id": 1, "name": "Главный судья" },
    { "id": 2, "name": "Судья" }
  ]
}
```

Полученный `id` передаётся в `position_id` при назначении судьи.

Для выбора судьи администратор использует реестр с фильтром роли:

```http
GET /api/v1/admin/users?role=judge&search=иван
```

В ответе будут только активные пользователи, у которых назначена роль `judge`.
