# Публичный API справочников

Все endpoints доступны без авторизации и возвращают `200 OK` с объектом `data`. Пустой справочник возвращается как `{"data":[]}`. При внутренней ошибке сервер возвращает `500 Internal Server Error` и `{"message":"внутренняя ошибка сервера"}`. Запрос с другим HTTP-методом возвращает `405 Method Not Allowed`.

## Дисциплины

```http
GET /api/v1/disciplines
```

```json
{
  "data": [
    {
      "id": 1,
      "name": "программирование алгоритмическое"
    }
  ]
}
```

## Типы соревнований

```http
GET /api/v1/competition-types
```

```json
{
  "data": [
    {
      "id": 4,
      "name": "Чемпионат"
    }
  ]
}
```

## Уровни соревнований

```http
GET /api/v1/competition-levels
```

Поля `code` и `name` nullable в актуальной схеме и поэтому могут содержать `null`.

```json
{
  "data": [
    {
      "id": 2,
      "code": "regional",
      "name": "Региональный"
    }
  ]
}
```

## Возрастные группы

```http
GET /api/v1/age-groups
```

`min_age` и `max_age` могут быть `null`, если соответствующая граница не задана.

```json
{
  "data": [
    {
      "id": 3,
      "name": "Юниоры",
      "min_age": 14,
      "max_age": 17
    }
  ]
}
```

## Использование ID на frontend

Frontend не должен фиксировать числовые ID в коде. Например, форма создания соревнования сначала загружает `/api/v1/disciplines`, показывает пользователю поле `name`, а выбранный `id` отправляет как `discipline_id`:

```json
{
  "discipline_id": 1
}
```

Аналогично используются `competition_type_id` и `competition_level_id`. Возрастные группы нужны в сценариях, где API принимает `age_group_id`.

## Начальное заполнение

Команда из каталога `backend`:

```bash
make seed-reference
```

или:

```bash
go run ./cmd/seed-reference
```

Команда использует `DATABASE_URL` и идемпотентно добавляет шесть официальных дисциплин спортивного программирования. Повторный запуск не создаёт дубликаты и не изменяет существующие строки. Типы соревнований, уровни и возрастные группы автоматически не заполняются: согласованный набор значений для них в текущих проектных материалах отсутствует.

Добавляемые дисциплины:

- программирование алгоритмическое;
- программирование продуктовое;
- программирование систем информационной безопасности;
- программирование систем искусственного интеллекта;
- программирование робототехники;
- программирование беспилотных авиационных систем.
