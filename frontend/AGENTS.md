## UI Component Rules

- Always prioritize existing shadcn/ui components.
- Before creating a custom component, check whether
  shadcn/ui already provides a suitable solution.
- Use the shadcn skill and MCP server when applicable.
- Reuse components from @/components/ui.
- Install missing components via shadcn CLI.
- Follow existing design tokens and CSS variables.
- Never introduce a new component library without approval.
- Use Tailwind CSS for styling.
- Preserve accessibility and responsive behavior.
- Prefer component composition over duplication.
- Do not modify existing shadcn primitives unless necessary.
- Follow the project's existing UX patterns.
