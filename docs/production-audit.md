# Production-аудит frontend

Дата проверки: 28 октября 2026 года.

## Область проверки

Проверены публичный лендинг, вход, регистрация, выбор и переключение ролей, публичный профиль, рабочая область и все маршруты:

- обзор, профиль, уведомления;
- соревнования и карточка соревнования;
- заявки, результаты, разряды и антидопинговые документы;
- тренеры и спортсмены, судейские назначения, сборные;
- реестр, рейтинг, календарные планы, сроки и файлы;
- роли и права, справочники, нормативы, проверки сертификатов и аудит.

Контракты сверены с файлами `doc/frontend-api.md`, `doc/competition-api.md`, `doc/competition-application-api.md`, `doc/competition-event-api.md`, `doc/competition-judges-api.md`, `doc/competition-results-api.md`, `doc/calendar-plan-api.md`, `doc/reference-api.md` и критериями жюри из `frontend/references`.

## Исправленные проблемы

### Критические сценарии

- Поиск спортсмена тренером переведён на документированную ручку `GET /api/v1/coach/participants`. Административное разрешение `registry.read` больше не требуется.
- В связях тренера, заявках, сборных и формах участия технические ID заменены на ФИО и названия дисциплин.
- Назначение судей использует список пользователей с ролью `judge` и справочник судейских должностей вместо ручного ввода ID.
- Добавлен полный административный жизненный цикл соревнования: восстановление собственных соревнований, отправка на проверку, публикация, возврат на доработку и отмена.
- Черновики и соревнования на проверке доступны после повторного входа, а не только из `sessionStorage` текущей вкладки.
- Для снятия судьи, завершения связи и отзыва заявки добавлено подтверждение опасного действия.
- Административная очередь антидопинговых сертификатов загружается из API; пользователю показывается ФИО, а скачивание выполняется авторизованным запросом.
- В пользовательском разделе антидопинга добавлено скачивание загруженного сертификата.

### API и модели

- Добавлены административные endpoints соревнований и типы истории статусов.
- Добавлены список антидопинговых сертификатов, справочник судейских должностей и поиск пользователей по роли.
- Добавлены загрузка и удаление PDF-протокола.
- Добавлен алиас permissions активной роли.
- Добавлены типы и клиент поиска спортсменов тренером.
- Повторяющаяся логика скачивания Blob вынесена в `shared/lib/download.ts`.

### UX, адаптивность и доступность

- Все рабочие экраны используют единую максимальную ширину и общий тулбар там, где нужны поиск, фильтры или создание.
- Мобильные диалоги отображаются снизу, имеют ограничение высоты, прокрутку, handle и жест закрытия вниз.
- Маски прокрутки исключены из диалогов и выпадающих списков, поэтому контент и Select больше не становятся полупрозрачными.
- Для обязательных и некорректно заполненных полей добавлены единые красные состояния.
- Расширены человекочитаемые подписи статусов соревнований и заявок.
- Удалены неиспользуемые OAuth-заглушки, production-консоль профиля и предупреждения ESLint.
- Изображение на экране авторизации переведено на `next/image`.
- Добавлены понятные loading, empty, error, forbidden и disabled-состояния для основных маршрутов.

## Backend-блокеры

1. Нет отдельного endpoint переключения активной роли без изменения набора назначенных ролей. Текущий PATCH выбора ролей подходит только для самостоятельно выбираемых ролей и не позволяет безопасно переключать системную роль администратора.
2. Нет перехода `published -> registration_open`, хотя подача заявки разрешена только при `registration_open`. Поэтому сквозной сценарий «создать, опубликовать и сразу открыть регистрацию» невозможно завершить.
3. Нет публичного справочника судейских категорий. При подаче заявки судьи frontend вынужден запрашивать технический `category_id`.
4. Нет endpoint результатов конкретного спортсмена для тренера. При подаче тренером заявки на разряд невозможно показать корректный список результатов спортсмена без ручного `result_id`.
5. Для командной настройки зачёта нет специализированного контракта кандидатов, объединяющего одобренные заявки и команды с правами пользователя. Существующие ручки требуют несвязанные permissions; безопасный универсальный UI без расширения прав невозможен.
6. Реестр предоставляет только текущую XLSX-выгрузку. Для отчёта о динамике численности нет временного ряда и параметров периода.
7. Рейтинг API не поддерживает фильтр по возрастной группе и не возвращает детализацию формулы по каждому результату.
8. Нет endpoint формирования проекта приказа по сборной.
9. Нет endpoint шаблона согласия законного представителя, поэтому кнопка шаблона при регистрации не может выполнять реальное действие.
10. Административные списки сертификатов и связей не содержат ФИО. Frontend временно обогащает их публичными профилями, что создаёт дополнительные запросы.

## Проверки

- `npm --prefix frontend run lint` — успешно, без предупреждений.
- `npm --prefix frontend run build` — успешно, TypeScript и production-сборка проходят.
- HTTP smoke-test основных публичных и workspace-маршрутов — все проверенные маршруты вернули `200`.
- `git diff --check` — выполняется в финальной проверке.

## Оставшиеся ограничения проверки

- В текущей среде не был доступен управляемый браузер, поэтому визуальная проверка всех ролей на ширинах 320, 375, 430, 768, 1024 и 1440 px не выполнена автоматически.
- Полные end-to-end сценарии с реальными ролями и данными требуют работающего backend, seed-аккаунтов и тестовой базы.
- Сценарии, перечисленные в разделе backend-блокеров, нельзя считать production-ready до изменения контрактов.

Frontend успешно собирается и основные безопасно исправимые проблемы устранены, но приложение нельзя объявить полностью production-ready до снятия перечисленных backend-блокеров и визуального E2E-прогона на целевых разрешениях.
