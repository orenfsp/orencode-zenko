Комплексная цифровая платформа для автоматизации процессов регионального отделения Федерации спортивного программирования (ФСП) Оренбургской области. Решение объединяет в себе учёт спортсменов, тренеров, судей и организаций, ведение календаря соревнований, работу с разрядами, формирование сборной и генерацию отчётной документации.

## 🚀 Технологический стек

*   **Backend:** Go (Golang)
*   **Frontend:** Next.js, React, TypeScript, Tailwind CSS
*   **Database:** PostgreSQL
*   **Infrastructure:** Docker, Docker Compose

## 📦 Быстрый запуск (Docker Compose)

Вся инфраструктура проекта (БД, бэкенд, фронтенд) упакована в Docker. Для запуска вам потребуется только установленный Docker и Docker Compose.

1. Клонируйте репозиторий:
   ```bash
   git clone <repo-url>
   cd <repo-url>
   ```
2.0 На всякий случай рекомендуем сбросить старую сборку и кэш:
```bash
docker compose down -v
```
2.1 Запустите сборку и старт контейнеров:
   ```bash
   docker compose --env-file backend/.env up --build -d
   ```

3. Откройте приложение в браузере:
   *   **Frontend (UI):** `http://localhost:3000`
   *   **Backend (API):** `http://localhost:8080`

> ⚠️ **Важно:** База данных автоматически наполняется демонстрационными данными (фиктивные ФИО, соревнования и протоколы) при первом запуске. Пароли и персональные данные в демо-версии являются вымышленными и соответствуют требованиям кейса.

## ✅ Реализованные сценарии

### Заявки на соревнования

Заявки подаются на конкретный зачёт из карточки соревнования. Регистрация разрешена только при статусе соревнования `registration_open` и внутри интервала `registration_starts_at`—`registration_ends_at`. Действующий антидопинговый сертификат проверяется существующим триггером PostgreSQL.

Статусы заявки: `pending` — ожидает решения, `approved` — одобрена, `rejected` — отклонена, `withdrawn` — отозвана спортсменом. Одобренные заявки автоматически попадают в существующую выборку участников модуля результатов.

Роли и права:

- спортсмен подаёт заявку за себя, просматривает её статус и отзывает ожидающую заявку до закрытия регистрации;
- тренер выбирает спортсмена только из подтверждённых связей `user_coach` по дисциплине зачёта и видит заявки своих подопечных;
- администратор с разрешением `competition_applications.review` просматривает, фильтрует, одобряет и отклоняет заявки.

API:

Подробные тела запросов, ответы и коды ошибок приведены в [документации API заявок](./doc/competition-application-api.md).

| Метод | Маршрут | Назначение |
| :--- | :--- | :--- |
| `POST` | `/api/v1/competition-applications` | Подать заявку за себя или подтверждённого подопечного |
| `GET` | `/api/v1/competition-applications/my` | Свои заявки и заявки подтверждённых подопечных |
| `GET` | `/api/v1/competition-applications/{id}` | Просмотреть доступную пользователю заявку |
| `POST` | `/api/v1/competition-applications/{id}/withdraw` | Отозвать собственную ожидающую заявку |
| `GET` | `/api/v1/admin/competition-applications` | Очередь федерации; фильтры `event_id`, `status`, `limit`, `offset` |
| `GET` | `/api/v1/admin/competition-applications/{id}` | Просмотреть заявку для рассмотрения |
| `POST` | `/api/v1/admin/competition-applications/{id}/approve` | Одобрить заявку |
| `POST` | `/api/v1/admin/competition-applications/{id}/reject` | Отклонить заявку |

Полный сценарий проверки:

1. Выполнить `make seed-rbac` в `backend`, чтобы синхронизировать разрешение `competition_applications.review` для административных ролей.
2. У спортсмена должен быть действующий антидопинговый сертификат, а у соревнования — открытая регистрация и опубликованный зачёт.
3. Спортсмен открывает `/workspace/competitions/{id}` и нажимает «Подать заявку» напротив зачёта.
4. Заявка появляется на `/workspace/applications?type=competition` со статусом `pending`.
5. Администратор открывает ту же вкладку, фильтрует очередь и одобряет либо отклоняет заявку.
6. Спортсмен видит новый статус; после одобрения заявка учитывается при настройке таблицы результатов зачёта.
7. Счётчик ожидающих заявок на дашборде уменьшается, поскольку он читает только статус `pending`.

### Обязательный функционал
| № | Сценарий | Как проверить |
| :--- | :--- | :--- |
| 1 | **Фронтенд и адаптивность** (стилистика ФСП, адаптив под мобилки/ПК) | Открыть `localhost:3000`, проверить в DevTools (режим мобильного устройства) |
| 2 | **Бэкенд и управление контентом** | Проверка работы API, наполнение БД через админку федерации |
| 3 | **Ролевая модель** (Федерация, Спортсмен, Тренер, Судья; смена ролей) | Войти под тестовым аккаунтом с несколькими ролями (например, Тренер+Судья), переключить роль в ЛК |
| 4 | **Календарь, заявки, протоколы** | Федерация создает соревнование -> Спортсмен подает заявку -> Федерация одобряет -> Ввод результатов -> Генерация протокола |
| 5 | **Разряды и категории** (Заявки, присвоение, контроль сроков) | Подача заявки на разряд спортсменом -> Одобрение Федерацией -> Отображение срока действия |
| 6 | **Реестр и динамика численности** | Переход в раздел "Отчеты", генерация отчета "Численность занимающихся" (выгрузка .xlsx) |
| 7 | **Рейтинг и формирование сборной** | Раздел "Рейтинг", фильтрация по возрастным группам, выгрузка проекта приказа |
| 8 | **Документы и отчеты** | Формирование протокола (.docx/.pdf) из карточки соревнования |
